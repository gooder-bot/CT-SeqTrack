# B2-v2 seed42：Search Evidence 与联合融合技术复核

更新时间：2026-08-02

## 技术结论

**B2-v2 full 有正信号，但本轮不能按预注册规则宣布正式涨点或晋级。** full
在 epoch60 达到 `54.132 Success / 64.755 Precision`。相对当前最强且最接近的
历史 B0（`53.360/64.382`），差值为 `+0.772/+0.373`：Success 通过 `+0.5`
门槛，Precision 没有达到 `+1.0`。late-3（epoch50/55/60）为
`54.462/66.013`，相对 B0 为 `+1.557/+2.909`，说明后期正信号不是只来自一个
偶然 checkpoint；但缺少同 commit、同运行环境的 matched B0，正式判定仍为
`HOLD_B2V2_PROMOTION`。

**旧 search-only 明确不涨点。** 它在 epoch60 为 `49.655/56.392`，相对历史
B0 下降 `3.705/7.990`，late-3 也下降 `3.474/7.511`。更重要的是，这组配置是
旧 long-tube + 75/25 token 分配，不是新 `TrajectorySearchEvidence` 的
search-only 消融，因而不能用 `full − search-only` 归因 motion 或 Search
Evidence 的净贡献。

**full 的可观测收益目前更像来自 physical prior + 新 observation-default joint
fusion，而不是 search candidate。** epoch60 训练中 search geometry/candidate
只有 `23.29%` 有效，search 被三候选 gate 选为 argmax 的比例仅 `0.104%`。
motion prior 则在 candidate0、非零 candidate、gap2、gap4 上分别比 constant
velocity 降低 RMSE `6.60%/12.81%/16.83%/21.58%`；同时 joint final 的一步
xy error 为 `0.236 m`，低于 observation 的 `0.247 m`。因此当前证据支持
“motion 与保守融合产生了小幅正信号”，不支持“Search Evidence 已贡献涨点”。

## 主结果：full 只部分通过 epoch60 门槛

主结果固定使用 epoch60；late-3 是 epoch50/55/60 的算术平均；best 只用于诊断。
所有分数均为 nuScenes v1.0-mini Car normal cadence、seed42 的 12 个无平滑
validation 点。

| 运行 | final Success | final Precision | late-3 Success | late-3 Precision |
|---|---:|---:|---:|---:|
| 新 SeqTrack control（异常低） | 31.684 | 31.337 | 31.138 | 30.640 |
| 旧 search-only | 49.655 | 56.392 | 49.431 | 55.593 |
| **B2-v2 full** | **54.132** | **64.755** | **54.462** | **66.013** |
| 历史原始 SeqTrack | 50.986 | 59.962 | 50.108 | 58.863 |
| 历史 CT-v2 B0 guardrail | 53.360 | 64.382 | 52.905 | 63.104 |
| B1motion-v3 standalone | 52.655 | 61.835 | 52.050 | 61.206 |

相对不同对照的含义必须分开：

| 比较 | Δ final S/P | Δ late-3 S/P | 可得结论 |
|---|---:|---:|---|
| 旧 search-only − 历史 B0 | −3.705 / −7.990 | −3.474 / −7.511 | 旧搜索路径失败 |
| B2-v2 full − 历史原始 SeqTrack | +3.147 / +4.793 | +4.354 / +7.150 | 超过论文原始数值参考，但不是同代码消融 |
| B2-v2 full − 历史 B0 | +0.772 / +0.373 | +1.557 / +2.909 | 有正信号；epoch60 Precision 未过门槛 |
| B2-v2 full − B1motion-v3 | +1.477 / +2.920 | +2.412 / +4.807 | 搜索/联合结构之后数值更高，但不是 matched search ablation |

full 在 epoch55 达到本轮 best `54.918/66.700`，epoch60 仍保持
`54.132/64.755`。best 不替换 final，但 late-3 全部高于历史 B0，说明应保留
B2-v2 做归因，不应像旧 B2 一样直接废弃。

## 新 SeqTrack control 是异常训练轨迹，不能作为唯一 baseline

新 control 完整跑满 60 epoch、12 次验证且没有 NaN，但 final 只有
`31.684/31.337`；12 个验证点的 best 也只有 epoch5 Success `32.303` 和
epoch10 Precision `33.793`。它与历史原始 SeqTrack 的前 3 个 training batch
`loss_total` 逐 float 完全相等，从 step3 开始出现微小差异，随后训练轨迹显著
分叉。这更符合同初始化下的随机训练流/非确定性被递归评测放大，而不是配置从一开始
就完全不同。

该 run 位于独立 `seqtrack` 仓库，未生成 `run_provenance.json`；当前仓库 HEAD
为 `2972678` 且工作区存在 KITTI/CLI 等未提交改动。hparams 能确认
seed42、batch16、workers4、60 epoch、nuScenes-mini Car，但不能恢复运行时精确
commit、dirty snapshot 与数据 selection hash。因此：

- `full − 新 control = +22.449/+33.418` 只是数值差，不能当成 B2 净增益；
- 新 control 不是崩溃/残缺结果，但属于极差训练 basin；
- 下一次正式判定必须补同 `a486a36`、同 workers、同数据 hash 的 CT-v2 B0。

## Search 的首要问题是“证据饥饿 + gate 双重抑制”

### 1. endpoint extension-only 只有约四分之一样本可用

epoch60 的 `search_v2_geometry_valid_rate` 和
`search_v2_candidate_valid_rate` 都是 `23.29%`。这是当前实现先取紧凑 endpoint
crop，再调用 `_extension_only` 删除 B0 crop 已有点、去重，最后要求至少 3 个
extension point 的直接结果。设计保护了 B0 的 1024 点和采样 RNG，但也让搜索分支
在约 `76.71%` 样本上完全无候选。

所有样本平均只有 `3.679` 个前景 extension point；该均值包含无效行，不能直接
当作有效 crop 的前景点数。targetness/vote/proposal loss 在 epoch60 已降至
`0.0086/0.0167/0.0136`，说明 encoder 在获得监督的有效样本上能学习局部证据；
当前更明确的结构瓶颈是证据覆盖率，而不是“128 点网络完全没收敛”。

### 2. observation bias 与 `log(confidence)` 把 search 的初始门槛叠加得过高

gate 初始 bias 是 `[4.6, 0, 0]`，而 search logit 在 softmax 前还要加
`log(search_confidence + ε)`。epoch60 全样本平均 confidence 为 `0.147`，仅这一项
约等于 `−1.92`；叠加 observation bias 后，search 在有效样本上也需要弥补约
`6.5` 的先验 logit 差。最终 checkpoint 的 gate bias 仍为
`[4.548, 0.021, 0.097]`，几乎保留初值；confidence head bias 为 `−2.593`。

这套安全设计成功避免了 search 抢走 B0，但和仅 `23.29%` 的 candidate availability、
自然类别频率 CE 一起，使 search argmax rate 在 epoch20/30/40/50/60 仅约
`0.015%/0.084%/0.079%/0.084%/0.104%`。换言之，模型学会了“不用 search”，
而不是学会了“何时可靠地用 search”。

### 3. confidence 的监督目标与部署所需的 helpfulness 不一致

confidence 只监督 endpoint crop 中是否至少有 3 个目标点；gate 真正需要的是
“search proposal 是否比 observation 至少好 0.05 m”。目标点存在不保证中心投票
比 observation 更准，因而 `log(confidence)` 既不能表达相对收益，还会额外压低
稀有 search 类。下一版应让 reliability 直接拟合 proposal advantage/quality，
而不是继续把 point existence 当成最终可用性。

## Motion 学到了，但 joint fusion 的真实递归贡献仍需同 checkpoint 归因

epoch60 的物理 prior 诊断为：

| 分支 | learned RMSE | constant-velocity RMSE | 相对改善 |
|---|---:|---:|---:|
| candidate0 main | 0.181 m | 0.194 m | 6.60% |
| nonzero candidates | 0.252 m | 0.289 m | 12.81% |
| gap2 auxiliary | 0.479 m | 0.576 m | 16.83% |
| gap4 auxiliary | 1.120 m | 1.429 m | 21.58% |

因此 physical prior 不是本轮首要失败点。训练的一步误差从 observation 的
`0.247 m` 降到 joint final 的 `0.236 m`，改善约 `4.49%`；但 motion candidate
单独误差为 `0.328 m`，说明收益依赖条件融合，而不是 motion proposal 普遍优于
observation。一步训练误差并不等价于 recursive tracking 指标，必须用同一
checkpoint 的候选禁用实验确认 full 的 `+0.772/+0.373` 到底来自 motion 修正、
search 修正还是训练期共同表征。

## 当前日志还有两处诊断盲区

第一，`joint_search_error` 对 invalid search 行没有 mask；无效 proposal 被置零，
因此 epoch60 的 `0.788 m` 不能解释为“有效 search proposal 的条件误差”。第二，
`joint_search_helpful_precision=1.11%` 是训练 batch 级、分母 clamp 后再求 epoch
mean 的值，且 search 几乎从不被选择；它不等于计划中的 validation endpoint
helpful precision ≥70%。当前没有验证阶段的 gate probability、oracle 类别频率、
候选误差和 tracklet id，故 search 的条件精度与统计区间都无法计算。

两个 B2 run 当时并行占用同一物理 GPU2。epoch60 日志中的 FPS 可受竞争影响，
不能用于判断“runtime 增幅不超过 15%”；需要单进程同卡短 benchmark。

## 判定与修改顺序

当前登记：

```text
LEGACY_SEARCH_ONLY_NO_GO
B2V2_NORMAL_SIGNAL_POSITIVE
B2V2_EPOCH60_SUCCESS_GATE_PASS
B2V2_EPOCH60_PRECISION_GATE_FAIL
B2V2_LATE3_GUARDRAIL_PASS_VS_HISTORICAL_B0
B2V2_SEARCH_CONTRIBUTION_NOT_ESTABLISHED
HOLD_B2V2_PROMOTION
```

优先做不重训的 attribution，再决定 B2-v2.1：

1. 用 full epoch60 `last.ckpt` 在同一 mini_val endpoint 上跑四个推理模式：full、
   observation-only、motion-only、search-only；候选值不变，只改 validity/ramp。
2. 导出每个 endpoint 的 obs/motion/search/final/GT、candidate validity、confidence、
   targetness mass/entropy、三类 gate probability、oracle 类、previous prediction
   error 与 tracklet id；对 on/off 做 tracklet-level paired bootstrap。
3. 修正日志：search error 只在 valid 行聚合，同时记录 valid-search helpful rate、
   selected-search helpful precision、oracle search prevalence 和 correction norm。
4. 补同 commit `a486a36`、scratch、seed42、workers4 的 matched B0 60 epoch。
   只有相对它的 epoch60 同时达到 `+0.5/+1.0`，才运行 seed43/44。
5. 若归因确认 search 不贡献，再改 B2-v2.1：保留紧凑 endpoint crop 和独立 128
   点，但允许 endpoint crop 的全部点进入 source-aware encoder，并增加
   baseline-overlap flag，避免 extension-only 造成 77% invalid；不要退回长 tube。
6. 将 search gate 改为 availability 与 utility 分离：confidence/utility 监督相对
   observation 的 proposal advantage，valid search 上使用 pairwise ranking 或
   regret-aware loss；移除未经校准的 `log(confidence)` 二次惩罚。仍保留 observation
   fallback、bounded correction 和 warmup。

在以上归因完成前，不启动 seed43/44、gap1124、random20、burst-drop 或论文
search 消融长训。

## 数据与方法边界

- 训练集：nuScenes v1.0-mini `mini_train` Car，5051 frames、274 tracklets；
  验证集：`mini_val`，2285 frames、106 tracklets。
- 新 B2 两组均为 seed42、batch16、workers4、scratch 60 epoch、每 5 epoch
  validation，共 75,720 optimizer steps；两者 provenance commit 都是
  `a486a3612b6d865bd44a8f14eb63c6e92ae1949f`。
- full 使用 `03_ct_motion_search_v2.yaml`；旧 search-only 使用
  `05_seqtrack3d_search_only.yaml`，后者不是新版 Search Evidence ablation。
- 本报告是描述性与诊断性分析，不是因果模块归因；只有一个 seed，没有 endpoint
  级 paired bootstrap、置信区间或 same-commit B0。
- 可复现入口：`python tools/analyze_b2_search_v2.py`。原始重算表位于
  `compare_results/data/b2_search_v2_seed42_20260802_*.csv`。
