## 1. 技术结论

本次回传的两个正式实验均来自 clean commit `1357923ec59b947e626916d84290bbf44dfa8899`，使用 nuScenes `mini_train`、seed42、batch size 16、workers 0。归档 SHA256 与同行校验文件完全一致：

```text
fd1e48922cb595cee154ef463dbb2f25f2c855dd8da3b1587c37d8610dc3b9e9
```

两项阶段决策如下：

| 阶段 | 正式决策 | 解锁内容 | 不能据此声称 |
| --- | --- | --- | --- |
| M0-3 | `GO_M2_PROPOSAL_INNOVATION` | 实现有界 proposal innovation，并准备一次预注册 seed42 `true/fixed/shuffled` | 已经提高 tracking Success/Precision |
| M0-4 | `FREEZE_M1_SHARED_SE2` | M1 只使用 shared SE(2) candidate augmentation；第一版不使用 smooth drift | candidate jitter 是 A2 所有退化的唯一原因 |

**整体判断**：M0-3 给出了目前最强的正向机制证据——在 crop-reachable、full-history、非重采样 endpoint 上，冻结 dynamics proposal 不仅具有 oracle 互补空间，本身也明显优于 observation proposal。M0-4 则关闭了 augmentation 方案选择：逐历史帧独立 candidate offset 会制造不物理的速度和加速度，因此 M1 必须共享同一个 SE(2) 变换。由于 M0-2 的 A/B/C 四协议冻结输出与 path variance 尚未完成，M0 不能整体标记为完成。

## 2. M0-3：Proposal innovation 有可用空间

### 2.1 样本流与主 cohort

正式输出共 `11,424` 行；按预注册条件逐层筛选：

```text
全部 endpoint              11,424
非重采样                    9,340
完整历史                    7,165
crop reachable              5,227
dynamics valid              5,227
primary candidate0          1,311 endpoints / 213 tracklets
```

四个 candidate 的 eligible endpoint 数量为 `1311/1304/1309/1303`，没有明显 candidate 构成失衡。主 cohort 的 observation、dynamics 与线段 oracle 中心误差为：

| Proposal | Mean error | Median error | P95 error |
| --- | ---: | ---: | ---: |
| `d_obs` | 1.349 m | 0.364 m | 6.028 m |
| `d_dyn` | 0.309 m | 0.118 m | 1.277 m |
| segment oracle | 0.232 m | 0.092 m | 0.987 m |

oracle 相对 observation 的平均收益为 `1.118 m`，中位数为 `0.214 m`；`76.20%` endpoint 的收益不低于 `0.05 m`。去除 gain 最大的 5% endpoint 后，平均收益仍为 `0.816 m`，所以结论并非由少量极端长尾独占。

### 2.2 非 oracle 稳健性检查

线段 oracle 的收益按构造不会为负，因此仅报告 oracle gain 不足以证明 dynamics proposal 真正可用。对原始 `d_obs/d_dyn/d_gt` 独立复算后：

- `d_dyn` 相对 `d_obs` 的平均误差改善为 `1.040 m`，中位数为 `0.175 m`；
- `81.31%` endpoint 上 `d_dyn` 更准确，`71.09%` endpoint 的改善不低于 `0.05 m`；
- 以 tracklet 为重采样单位，平均改善为 `0.803 m`，95% bootstrap CI 为 `[0.633, 0.988] m`；
- `87.32%` tracklet 的平均改善为正；
- oracle 在 dynamics 之上继续提供的平均额外改善只有 `0.078 m`。

这说明 M0-3 的正信号主要来自已经训练好的 dynamics proposal，而不是 oracle 沿线段事后选择制造的假象。proposal innovation 的作用应是**安全地在 observation 与 dynamics proposal 之间选择或插值**，不是重新证明 dynamics 是否含信息。

### 2.3 Long-gap 与 alpha 行为

在 `current_delta_t >= 1 s` 的 long-gap 子集上有 `417` 个 endpoint、`133` 个 tracklet：oracle gain 均值 `0.988 m`、中位数 `0.127 m`，`66.91%` endpoint 的 gain 不低于 `0.05 m`。tracklet bootstrap 的均值为 `0.717 m`，95% CI `[0.493, 0.967] m`，支持 long-gap 场景存在互补性。

最优线段系数 `alpha` 的分布为：

| `alpha` 区间 | 比例 |
| --- | ---: |
| `alpha = 0` | 9.38% |
| `0 < alpha < 1` | 47.98% |
| `alpha = 1` | 42.64% |

平均 `alpha=0.775`。这提示 M2 的 gate 不能继续保持当前约 `2e-5` 的近关闭状态，但也不能把默认值直接设成 1：仍有约一半 endpoint 需要内部插值或 observation 端点。正式实现必须 zero-init、受界，并保留 invalid-history 回退。

## 3. M0-4：冻结 shared SE(2) augmentation

### 3.1 独立 candidate jitter 制造强伪导数

正式输出共 `20,204` 行，其中 `13,934` 行满足 full-history；重采样率为 `19.13%`。四个 candidate 的 full-history usable 数量为 `3484/3481/3482/3487`，构成平衡。

candidate0 作为无扰动基准，其 velocity/acceleration jitter 精确为 0，sanity check 通过。对 candidate1/2/3 的 `10,450` 个非零候选：

| 指标 | Mean | P50 | P95 | 预注册阈值 | P50 / 阈值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| velocity jitter | 0.627 m/s | 0.611 m/s | 1.022 m/s | 0.05 m/s | 12.22× |
| acceleration jitter | 2.202 m/s² | 2.128 m/s² | 3.993 m/s² | 0.10 m/s² | 21.28× |

该量级已经远超“数值噪声”解释。逐历史帧独立采样 candidate offset 会把彼此不连续的框扰动直接解释为速度和加速度，破坏 dynamics supervision 的物理语义。

### 3.2 对 dynamics proposal 的实际影响

官方非配对统计中，candidate0 的 dynamics proposal mean error 为 `0.157 m`，非零 candidates 为 `0.168 m`，差约 `+0.0105 m`。为排除 endpoint 构成差异，进一步按相同 endpoint 与 candidate0 配对：

- 共 `8,515` 个配对比较，覆盖 `2,904` 个 endpoint key 与 `235` 个 tracklet；
- 非零 candidate 相对 candidate0 的 mean error delta 为 `+0.0104 m`，中位数 `+0.0033 m`；
- tracklet bootstrap 95% CI 为 `[+0.0093, +0.0155] m`；
- `81.70%` tracklet 的平均 delta 为正；candidate1/2/3 各自的 bootstrap CI 也全部高于 0。

因此，独立 candidate jitter 对 proposal accuracy 的负效应是稳定的；但其绝对均值约为 1 cm，明显小于伪速度/伪加速度本身的量级。合理结论是：它会污染 dynamics 学习并应被修复，但不能单独解释旧 A2 在所有协议上的失败。

### 3.3 M1 augmentation 决策

第一版 M1 正式冻结为：

```text
对同一个训练样本的全部历史框施加同一个 shared SE(2) 变换；
当前帧、历史轨迹、candidate 坐标与 Dynamics label 保持同一物理坐标关系；
Dynamics velocity/acceleration label 从 canonical 或一致变换后的轨迹计算；
不在第一版加入 smooth drift，也不根据后续 tracking 涨跌反向修改该选择。
```

shared SE(2) 的目标不是“自动涨点”，而是消除一个已确认的监督污染源，并为 M2 的 proposal innovation 提供可解释的状态传播输入。

## 5. 限制与不能外推的结论

1. M0-3 是 training-sampler 上的 GT-history、offline、crop-reachable oracle，不是 recursive online tracking 结果。
2. primary cohort 排除了 `18.24%` resampled endpoint；M0-4 也观察到 `19.13%` 重采样，后续实现必须记录并约束 fallback/resample 行为。
3. M0-3 只在 gap1124 入口正式运行；standard、burst 与 unseen cadence 尚未形成同类 oracle 验证。
4. sparse `target_points <= 5` 只有 3 个样本，不能支持 sparse 场景结论；long-gap 子集有足够样本，可以作为当前正式挑战分桶。
5. M0-4 证明的是 augmentation 物理一致性问题，不是最终 tracking 指标的因果增益。
6. 两项实验都只解锁后续工程和受控试验；在 seed42 `true/fixed/shuffled` 与 standard guardrail 通过前，不能把 M1/M2 写成已验证贡献。

## 6. 下一步执行顺序

1. **先实现 M1 shared SE(2) 数据基础**：统一 sample-level transform、canonical dynamics label、开关与单元测试；关闭新逻辑时保持旧 A1 数据路径不变。
2. **实现 M2 proposal innovation**：使用 `innovation = clip(d_dyn - stopgrad(d_obs), R(delta_t))`，并令 `d_final = d_obs + alpha * innovation`；删除正式候选中的完整位移直接相加语义。
3. **完成等价性与安全 smoke**：`alpha=0`/zero-init 必须恢复 A1；覆盖 invalid history、resampled/empty fallback、standard/gap/burst forward-loss-backward 和至少 2-step optimizer。
4. **并行完成剩余 M0-2**：冻结 A/B/C final checkpoint 的 standard、gap1124、burst-drop、unseen fixed-gap 与 evaluation-only path variance。完成前 M0 仍标记为进行中。
5. **冻结 clean commit 与唯一 seed42 配置后才启动正式训练**：只运行一次预注册 `true/fixed/shuffled`，不扫 gate/scale/bound 网格。除时间控制外保持 checkpoint、manifest、candidate、点采样和 optimizer steps 一致。
6. **按原门槛判断是否补多 seed**：standard 相对 A1 不低于 `-0.5 Success / -1.0 Precision`，且 gap1124 或 burst-drop 至少一项达到 `+1 Success / +2 Precision`；true-dt 还必须同时超过 fixed 与 shuffled。未通过则停止 M2 promotion，不补 seed43/44。

当前最合理的代码起点是 M1 shared SE(2) 数据层，而不是先调 M2 gate。原因是 M2 的 dynamics proposal 必须建立在物理一致的历史轨迹与监督上；否则会把已确认的 candidate 伪导数继续带入新公式。
