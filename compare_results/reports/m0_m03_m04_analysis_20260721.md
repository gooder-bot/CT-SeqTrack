## 1. 技术结论

本次回传的两个正式实验均来自 clean commit `1357923ec59b947e626916d84290bbf44dfa8899`，使用 nuScenes `mini_train`、seed42、batch size 16、workers 0。归档 SHA256 与同行校验文件完全一致：

```text
fd1e48922cb595cee154ef463dbb2f25f2c855dd8da3b1587c37d8610dc3b9e9
```

两项阶段决策如下：

| 阶段 | 正式决策 | 解锁内容 | 不能据此声称 |
| --- | --- | --- | --- |
| M0-3 | `GO_M2_PROPOSAL_INNOVATION` | 实现有界 proposal innovation，并准备一次预注册 seed42 `true/fixed/shuffled` | 已经提高 tracking Success/Precision |
| M0-4 | `FREEZE_M1_SHARED_SE2` | M1 只使用 shared SE(2) candidate augmentation；第一版不使用 smooth drift | candidate jitter 是 A2 所有退化的唯一原因 |

**整体判断**：M0-3 给出了目前最强的正向机制证据——在 crop-reachable、full-history、非重采样 endpoint 上，冻结 dynamics proposal 不仅具有 oracle 互补空间，本身也明显优于 observation proposal。M0-4 则关闭了 augmentation 方案选择：逐历史帧独立 candidate offset 会制造不物理的速度和加速度，因此 M1 必须共享同一个 SE(2) 变换。现有证据已经足以启动 M1/M2 的代码实现和安全验收，但不足以启动未经预注册的正式训练，更不足以宣称在线 tracking 涨点。由于 M0-2 的 A/B/C 四协议冻结输出与 path variance 尚未完成，M0 不能整体标记为完成。

## 2. M0-3：Proposal innovation 有可用空间

### 2.1 样本流与主 cohort

正式输出共 `11,424` 行；按预注册条件逐层筛选：

```text
全部 endpoint              11,424
非重采样                    9,340
完整历史                    7,165
crop reachable              5,227
dynamics valid              5,227
primary candidate0          1,311 endpoints / 213 tracklets
```

四个 candidate 的 eligible endpoint 数量为 `1311/1304/1309/1303`，没有明显 candidate 构成失衡。主 cohort 的 observation、dynamics 与线段 oracle 中心误差为：

| Proposal | Mean error | Median error | P95 error |
| --- | ---: | ---: | ---: |
| `d_obs` | 1.349 m | 0.364 m | 6.028 m |
| `d_dyn` | 0.309 m | 0.118 m | 1.277 m |
| segment oracle | 0.232 m | 0.092 m | 0.987 m |

oracle 相对 observation 的平均收益为 `1.118 m`，中位数为 `0.214 m`；`76.20%` endpoint 的收益不低于 `0.05 m`。去除 gain 最大的 5% endpoint 后，平均收益仍为 `0.816 m`，所以结论并非由少量极端长尾独占。

### 2.2 非 oracle 稳健性检查

线段 oracle 的收益按构造不会为负，因此仅报告 oracle gain 不足以证明 dynamics proposal 真正可用。对原始 `d_obs/d_dyn/d_gt` 独立复算后：

- `d_dyn` 相对 `d_obs` 的平均误差改善为 `1.040 m`，中位数为 `0.175 m`；
- `81.31%` endpoint 上 `d_dyn` 更准确，`71.09%` endpoint 的改善不低于 `0.05 m`；
- 以 tracklet 为重采样单位，平均改善为 `0.803 m`，95% bootstrap CI 为 `[0.633, 0.988] m`；
- `87.32%` tracklet 的平均改善为正；
- oracle 在 dynamics 之上继续提供的平均额外改善只有 `0.078 m`。

这说明 M0-3 的正信号主要来自已经训练好的 dynamics proposal，而不是 oracle 沿线段事后选择制造的假象。proposal innovation 的作用应是**安全地在 observation 与 dynamics proposal 之间选择或插值**，不是重新证明 dynamics 是否含信息。

### 2.3 Long-gap 与 alpha 行为

在 `current_delta_t >= 1 s` 的 long-gap 子集上有 `417` 个 endpoint、`133` 个 tracklet：oracle gain 均值 `0.988 m`、中位数 `0.127 m`，`66.91%` endpoint 的 gain 不低于 `0.05 m`。tracklet bootstrap 的均值为 `0.717 m`，95% CI `[0.493, 0.967] m`，支持 long-gap 场景存在互补性。

最优线段系数 `alpha` 的分布为：

| `alpha` 区间 | 比例 |
| --- | ---: |
| `alpha = 0` | 9.38% |
| `0 < alpha < 1` | 47.98% |
| `alpha = 1` | 42.64% |

平均 `alpha=0.775`。这提示 M2 的 gate 不能继续保持当前约 `2e-5` 的近关闭状态，但也不能把默认值直接设成 1：仍有约一半 endpoint 需要内部插值或 observation 端点。旧 residual 的 `scale=0.1` 与 `max_alpha=0.2` 相乘后，最多只能走完 proposal 线段的 `2%`，与本次 oracle 分布明显不匹配；新 M2 不应机械继承这个双重缩放，而应让一个可解释的 effective alpha 覆盖 `[0,1]`，再用 `R(delta_t)` 限制 innovation 的绝对范数。这里的 oracle 是未裁剪线段上限；若 `R(delta_t)` 触发，`alpha=1` 也只能到达朝向 `d_dyn` 的有界点，因此必须同时报告 clamp ratio，不能把 `0.232 m` oracle error 当成可实现保证。正式实现仍必须从显式 zero-scale 启动、受界，并保留 invalid-history 回退。

## 3. M0-4：冻结 shared SE(2) augmentation

### 3.1 独立 candidate jitter 制造强伪导数

正式输出共 `20,204` 行，其中 `13,934` 行满足 full-history；重采样率为 `19.13%`。四个 candidate 的 full-history usable 数量为 `3484/3481/3482/3487`，构成平衡。

candidate0 作为无扰动基准，其 velocity/acceleration jitter 精确为 0，sanity check 通过。对 candidate1/2/3 的 `10,450` 个非零候选：

| 指标 | Mean | P50 | P95 | 预注册阈值 | P50 / 阈值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| velocity jitter | 0.627 m/s | 0.611 m/s | 1.022 m/s | 0.05 m/s | 12.22× |
| acceleration jitter | 2.202 m/s² | 2.128 m/s² | 3.993 m/s² | 0.10 m/s² | 21.28× |

该量级已经远超“数值噪声”解释。逐历史帧独立采样 candidate offset 会把彼此不连续的框扰动直接解释为速度和加速度，破坏 dynamics supervision 的物理语义。

### 3.2 对 dynamics proposal 的实际影响

官方非配对统计中，candidate0 的 dynamics proposal mean error 为 `0.157 m`，非零 candidates 为 `0.168 m`，差约 `+0.0105 m`。为排除 endpoint 构成差异，进一步按相同 endpoint 与 candidate0 配对：

- 共 `8,515` 个配对比较，覆盖 `2,904` 个 endpoint key 与 `235` 个 tracklet；
- 非零 candidate 相对 candidate0 的 mean error delta 为 `+0.0104 m`，中位数 `+0.0033 m`；
- tracklet bootstrap 95% CI 为 `[+0.0093, +0.0155] m`；
- `81.70%` tracklet 的平均 delta 为正；candidate1/2/3 各自的 bootstrap CI 也全部高于 0。

因此，独立 candidate jitter 对 proposal accuracy 的负效应是稳定的；但其绝对均值约为 1 cm，明显小于伪速度/伪加速度本身的量级。合理结论是：它会污染 dynamics 学习并应被修复，但不能单独解释旧 A2 在所有协议上的失败。换言之，M1 更像必要的数据地基和方差控制，而不是预期单独带来大幅涨点的模块；真正的性能假设仍落在 M2 是否能把已经存在的 dynamics 优势安全转成在线结果。

### 3.3 M1 augmentation 决策

第一版 M1 正式冻结为：

```text
对同一个训练样本的全部历史框施加同一个 shared SE(2) 变换；
当前帧、历史轨迹、candidate 坐标与 Dynamics label 保持同一物理坐标关系；
Dynamics velocity/acceleration label 从 canonical 或一致变换后的轨迹计算；
不在第一版加入 smooth drift，也不根据后续 tracking 涨跌反向修改该选择。
```

shared SE(2) 的目标不是“自动涨点”，而是消除一个已确认的监督污染源，并为 M2 的 proposal innovation 提供可解释的状态传播输入。

## 5. 限制与不能外推的结论

1. M0-3 是 training-sampler 上的 GT-history、offline、crop-reachable oracle，不是 recursive online tracking 结果。
2. primary cohort 排除了 `18.24%` resampled endpoint；M0-4 也观察到 `19.13%` 重采样，后续实现必须记录并约束 fallback/resample 行为。
3. M0-3 只在 gap1124 入口正式运行；standard、burst 与 unseen cadence 尚未形成同类 oracle 验证。
4. sparse `target_points <= 5` 只有 3 个样本，不能支持 sparse 场景结论；long-gap 子集有足够样本，可以作为当前正式挑战分桶。
5. M0-4 证明的是 augmentation 物理一致性问题，不是最终 tracking 指标的因果增益。
6. 两项实验都只解锁后续工程和受控试验；在 seed42 `true/fixed/shuffled` 与 standard guardrail 通过前，不能把 M1/M2 写成已验证贡献。

### 6.1 代码审计对实现的约束

1. `datasets/sampler.py::motion_processing_mf` 当前为每个历史框分别调用 `sample_candidate_offset`。TWC 的共享 map 只保证两个 view 中同一绝对 frame 复用扰动，**不是**整条历史轨迹的 shared SE(2)。两者必须保留为不同语义。
2. 不能只把同一个 `[dx,dy,dtheta]` 重复传给每个 `getOffsetBB`。该函数在各框自身局部朝向中解释平移；同一数组可能产生不同的世界平移，仍会制造伪导数。正确实现应围绕共同 anchor 构造一个世界坐标刚体变换：

   ```text
   c_i'   = a + R(dtheta) (c_i - a) + R(yaw_a) [dx, dy]
   yaw_i' = yaw_i + dtheta
   ```

   其中 `a/yaw_a` 是最近历史 anchor；z、尺寸和历史时间不变。核心验收不是“随机数相同”，而是所有历史框满足同一个刚体变换，且在新 anchor 坐标中 pairwise trajectory 与 canonical trajectory 一致。
3. Dynamics label 必须先由未扰动 GT trajectory 和真实 `delta_t` 定义，再一致地表达进增强后的 anchor 坐标；禁止由 candidate `ref_boxs` 做差得到速度/加速度。candidate0 应逐元素保持旧路径。
4. `models/seqtrack3d.py` 的旧 `residual_limited/bounded_residual` 会归一化成 `residual`，随后 clamp 完整 `d_dyn` 并加到完整 `d_obs`。新方法应增加显式 `proposal_innovation` 模式，保留旧 `residual` 仅作历史负对照，避免静默改变旧实验语义。
5. `DynamicsResidualGate(init_alpha=0)` 通过 sigmoid 前把比例夹到 `1e-4`，实际 alpha 约 `2e-5`，并非严格 0；现有 `check_residual_dynamics.py` 也只要求 alpha `<1e-3`。M1/M2 必须增加显式 zero-scale/disabled path，使 step 0 的最终输出严格等于同提交 A1，而不是把“近零”写成“等价”。

### 6.2 正式训练前 E0–E6 门槛

- **E0 默认回归**：新开关默认关闭，candidate0 与旧 A1 batch 字段、loss 和输出在约定容忍度内一致。
- **E1 几何不变量**：shared transform 是一个真实 sample-level SE(2)，不是重复局部 offset；candidate1/2/3 非零且不会产生额外 velocity/acceleration jitter。
- **E2 label 不变量**：真实时间监督只来自 canonical GT；不同 candidate 只允许坐标协变，不允许物理速度/加速度标签改变。
- **E3 公式不变量**：`innovation=clip(d_dyn-stopgrad(d_obs), R(dt))`；`alpha=0`、`dynamics_valid=0`、warmup/disabled 时最终输出严格恢复 observation/A1。
- **E4 数值安全**：standard、gap1124、burst-drop 的真实 batch forward/loss/backward 全 finite，覆盖 full/invalid history、resampled/empty fallback。
- **E5 可训练性**：至少 2 个 optimizer steps；innovation branch 在启用后有 finite、非零梯度，同时修正量受界。
- **E6 可复现性**：唯一 seed42 配置、同 A1 初始化、固定 manifest/candidate/point sampling/optimizer steps/final checkpoint 口径，clean commit 和 provenance 完整。

只有 E0–E6 全部通过，才从 Engineering GO 升级为 Formal-training GO。

## 7. 下一步执行顺序

1. **先实现 M1 shared SE(2) 数据基础**：优先新建 `utils/candidate_utils.py` 和 `tools/check_candidate_shared_se2.py`，先完成 dataset-free 共同世界刚体变换单测；随后在 `datasets/sampler.py` 接入独立配置枚举，默认保持 legacy independent，并输出 canonical label 与审计字段。不要先改模型。
2. **再实现严格零初始化接口**：显式 disabled/zero-scale 路径；在同一 A1 权重和同一 batch 上比较 observation output、loss 与最终框。
3. **新增 M2 proposal-innovation 模式**：使用 `innovation = clip(d_dyn - stopgrad(d_obs), R(delta_t))` 和 `d_final = d_obs + alpha * innovation`；旧 full-displacement residual 只保留作可复现负对照。
4. **完成 E0–E5 smoke**：invalid history、resampled/empty fallback、standard/gap/burst forward-loss-backward 和至少 2-step optimizer。
5. **并行完成剩余 M0-2**：冻结 A/B/C final checkpoint 的 standard、gap1124、burst-drop、unseen fixed-gap 与 evaluation-only path variance。完成前 M0 仍标记为进行中。
6. **冻结 E6 后才启动正式训练**：只运行一次预注册 seed42 `true/fixed/shuffled`，不扫 gate/scale/bound 网格。
7. **按原门槛判断是否补多 seed**：standard 相对 A1 不低于 `-0.5 Success / -1.0 Precision`，且 gap1124 或 burst-drop 至少一项达到 `+1 Success / +2 Precision`；true-dt 还必须同时超过 fixed 与 shuffled。未通过则停止 M2 promotion，不补 seed43/44。

当前最合理的代码起点是 M1 shared SE(2) 数据层，而不是先调 M2 gate。原因是 M2 的 dynamics proposal 必须建立在物理一致的历史轨迹与监督上；否则会把已确认的 candidate 伪导数继续带入新公式。
