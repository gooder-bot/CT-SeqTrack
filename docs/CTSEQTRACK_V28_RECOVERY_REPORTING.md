# v28 闭环失跟与稀疏恢复报告

`endpoint_diagnostics.v28` 的 `recovery` 字段读取实际完整闭环 `final` 输出。固定采用 `benchmark_compat` IoU；这些定义只做报告，不进入训练采样、动作阈值拟合、checkpoint 选择或调参。

- 首次失跟：预测帧中第一次 `IoU < 0.1`；同时独立报告第一次 `IoU == 0`。一直未发生时帧号为 null，标记右删失并保留观测截止帧，不能把末帧伪装成失跟帧。
- 必须提供每条 tracklet 完整的 `frame0..T`，每帧恰好一次；报告按场景、tracklet、帧排序。重复或缺帧直接报错。初始化帧仍计入正式全帧 S/P，但不计入点数桶或连续稀疏段。
- 点数来自当前 B0 crop 正则采样前的原始测量数 `b0_raw_point_count`，兼容 `acquisition_base_raw_point_count`。`current_sampled_valid` 单独表示当前 B0 采样槽是否有有效测量。原始点数缺失为 unknown，不推断为 0；报告计数覆盖率。固定桶为 **0、1、2、3–10、11–50、>50、unknown**，各桶 S/P 为该桶预测帧逐帧贡献平均值乘 100，空桶为 null。
- 分别统计原始 **0 点空 crop** 连续段、**≤2 点兼容稀疏** 连续段；后者包含前者。记录每段起止帧、观测持续帧数、最长段和平均观测长度。缺原始计数会中断可观测区间，不跨未知帧拼接。段尾遇到序列结束或未知计数标为持续长度右删失；段首紧邻未知计数标为左删失。
- 段后成功返回定义为：该段结束后、下一同类段开始前，第一个 `final IoU >= 0.5` 的帧。遇到未知计数或序列结束也停止窗口。返回延迟为返回帧号减段尾帧号，紧接下一帧返回记 1。
- 每段另外记录段内是否曾 `IoU < 0.1`。`post_segment_returns` 包含所有段后的成功返回；只有曾失跟段才进入 `lost_segments` 与 `recovered_lost_segments`，避免把一直跟踪正常的空 crop 段误称为失跟恢复。
- 未在窗口内观测到成功返回记 `return_right_censored=true`，明确原因 `next_segment`、`missing_raw_count` 或 `sequence_end`，并记录实际观测随访帧数；不作为确定失败。`observed_recovery_fraction` 为已观测恢复数/曾失跟段数，是观测下界，未做生存分析校正；平均返回延迟只覆盖已观测返回。

该报告不使用 GT 筛帧，不改变原始全帧 S/P 分母，不从同状态的一步候选收益推断闭环恢复收益。比较不同模型时须分别完成同协议闭环评测。
