# V41 联合搜索 · KITTI Car

本轮只新增一个从头训练的联合组，比较对象是已完成的 V41 v3 uniform。历史 test 的第 58–60 轮平均 Success / Precision 为 67.97 / 79.93，第 60 轮为 68.79 / 80.62。联合组沿用 uniform 的主干、q0 中心损失、B1、MTP、单种子和优化步数。两个系统的多处差异只能用来评估整套方案。[历史结果](../artifacts/ct_checks/20261121_q0_final_review/REPORT.md) · [搜索审计和文献依据](../artifacts/ct_checks/20261121_joint_search_decision/REPORT.md)

## 一次预测怎样影响下一帧

| 条件 | 本帧与下一帧的行为 |
|---|---|
| 正常跟踪 | B0 保留原来的 1,024 个当前点预算；双区开启时主区和备用区的基础配额为 768 / 256。新局部头从当前采样点预测有符号的三维中心位移并精修，每帧可产生一个额外局部候选。 |
| 主区持续缺乏可信证据 | 本帧仍输出效用最高的可选框。独立运动状态用真实时间推进，弱输出不能充当新的速度测量。健康时每 1 秒巡查原云，连续两帧弱输出后，巡查间隔缩短至 0.2 秒。 |
| 外区出现候选 | 在未按 GT 预裁的当前扫描上构造非空 BEV 网格。车辆分、模板匹配和有界的运动距离代价用于生成至多 3 个不同位置。首次读取排名最高的位置，下一物理扫描优先复查待定位置。每次最多精裁一个区域、256 个唯一原始点。 |
| 出现测量写入 | q0、原 R、局部投票与远端投票分别携带自己的点 ID。可信写入要求身份胜出、几何预测通过及至少 3 个框内前景支持点。远端还要求有效模板和下一次扫描对待定位置的独立确认。大跳变重新建立运动基准，随后用相邻测量恢复速度。 |
| 首框稀疏 | 合法首框内至少 3 个唯一点才能建立固定模板。首框只有 0–2 点时，局部候选仍可用几何及竞争信息定位；两次相邻且无歧义的可信局部测量可建立延迟模板。当前扫描完全没有本车回波时，位置只能由历史运动等间接证据估计。 |

六个槽位依次是 q0、B1 先验、可信速度传播、原 R、局部投票、远端投票。位置效用仍监督 Success 和 Precision。联合组把几何头的监督事件定义为精确 3D IoU ≥ 0.5，并单独监督车辆身份。第一次远端提议可获得训练监督，在线选择还需满足确认条件。逐帧记录同时保留可生成资格、在线可选资格、支持点和最终选择，便于区分“没产生好框”和“好框产生后没被选中”。

## 困难样本如何进入主训练

独立辅助流用自身过去的预测运行整条训练轨迹。训练标签只用于事后挑选前缀、局部点监督和稀疏网格监督。回放库按重现、局部搜索漏采、可见时漂移和邻车竞争收集预测前的状态，下一轮最多替换每四个 branch 0 单步槽中的一个。主训练照常给 B0 梯度，辅助前向隔离 B0/B1，优化器仍按原主批次步进。完整轮次 checkpoint 同时保存回放库。

同扫描其他车辆标注用于网格车辆类别和实例负例。模板交换负例使用不同训练轨迹。新增损失的固定初始权重为前景、点投票和身份各 0.25，局部精修、模板交换、网格类别、网格匹配和网格偏移各 0.10。这组权重、巡查节奏及确认条件都需要由联合实验检验。

## 运行和比较

在服务器的活动仓库根目录使用新目录启动。配置继承 KITTI 数据路径、seed 42 和 60 轮配方，并自动在第 58–60 轮写入完整逐帧记录。

```bash
CFG=cfgs/ct_seqtrack/41_full_kitti_joint_search.yaml
RUN=output/v41_joint_search_kitti_car_seed42
python main.py --cfg "$CFG" --log_dir "$RUN"
python tools/compare_v41_joint_search.py --joint-run "$RUN"
```

比较工具读取同一联合运行的三份 test 记录和已有 uniform 压缩台账，核对 SHA、场景、物理车辆、扫描及官方 S/P。报告区分原云无本车点、并集遗漏和采样遗漏，并统计低纯度错写、几何错写、远端错接、健康轨新增失跟和超过 5 / 10 米的帧。外搜报告列出粗提议中心命中真值 BEV 范围的帧数、精裁实际得到至少 1 / 3 / 10 个本车点的帧数，以及新增候选单独贡献好框的帧数。重现恢复以连续三个物理扫描 IoU ≥ 0.5 计，保留中途再次无回波或轨迹结束仍未恢复的事件。

单目标延迟单独测。在已有第 60 轮权重上，以下命令让每次前向只处理一条轨迹，并关闭逐帧完整诊断。

```bash
python main.py --cfg "$CFG" --test --checkpoint "$RUN/formal_checkpoints/epoch=060.ckpt" \
  --log_dir "${RUN}_latency" --eval_split test --v41_joint_latency \
  --diagnostics_level summary --full_diagnostic_epochs
```

结果位于该评估目录的 `results.json`。P50 / P95 从已交付的端点开始，覆盖裁点、前向和状态提交，跳过前 10 个预测帧；数据加载与事后基准打分单独计算。历史 uniform 台账没有同口径的单目标耗时。

可把这个目录作为 `--latency-test "${RUN}_latency"` 加在比较命令中，将延迟与同一运行的 E60 结果关联。
