# v30 显存预算与训练效率取舍（2026-09-15）

用户补充：可以接受相对原B0约增加5GB显存，目标仍是涨分、完成三臂mini实验和论文。
据此，当前推荐默认是**直接计算有效点BN，保留拷贝优化与native分配器；局部重算改为可选**。
这是依据已有数据选择的起点，尚未在服务器比较两模式的吞吐，不能称为已证明的全局最优配置。

## 为什么调整上一次的默认值

本次B0事件第50步实际张量峰值6.89GiB，历史同batch16/FP32约3.89GiB，实际增量约3GiB。
33.86GiB的reserved包含缓存块，不能作为所有BN都必须重算的依据。
它也不能证明整个进程换成native默认分割后必定低于10GB：进程占用还包括缓存与CUDA工作空间。
原始证据见[故障分析](CTSEQTRACK_V30_CUDA_MEMORY_FIX.md)。

既然这部分实际激活增量可接受，首先应减少无意义分配和不必要重复计算。
直接计算保留有效性监督、原BN统计、相同前向和梯度；重算仅减少中间量驻留，不增加目标证据，
也没有改变B1/B2/B3的学习目标。两者设计上均不以精度换显存。

| 选择 | 当前决定 | 与本项目的关系 |
|---|---|---|
| bool排序改int64 | 保留 | 修复Full探索分支实际CUDA异常，动作语义不变 |
| 无效测量loss/BN/池化mask | 保留 | 稀疏/缺测不能伪装成真实前景证据 |
| 标量where、删除重复mask | 保留 | 减少拷贝，不损失观测信息 |
| native默认分配器、解除64MiB限制 | 保留 | 允许不同roll-in尺寸复用与拆分缓存大块 |
| 部分有效BN强制重算 | 改为默认关闭 | 用户已有可接受内存空间，先避免额外反向重算 |
| 改GN/LN、缩batch/历史、减768→256预算 | 此次不改 | 会引入新的训练或表示变量，无收益证据支持此次混入 |

## 文献如何支持这一取舍

Chen等的[Training Deep Nets with Sublinear Memory Cost](https://arxiv.org/html/1604.06174v2)
把计算图复用与重算区分开来：第3节讨论内存共享，第4节讨论丢弃中间量后重新计算。
第4.2节还专门提出保留卷积结果、重算BN/ReLU等低成本操作。因此上一轮局部BN重算有合理依据；
但第5.4节同样报告额外运行成本。文献的特定网络成本不能直接套到CT-SeqTrack。
本项目的判断是：在用户允许的内存预算内，优先完成更多有效实验，容量受限时再使用该技术。

PyTorch的[选择性重算说明](https://pytorch.org/blog/activation-checkpointing-techniques/)
进一步强调按操作代价和内存预算选保存/重算，而非无条件重算所有区域。
这支持保留一个明确开关。其较新编译/自动预算接口没有直接移植进当前PyTorch2.0服务器工程；
当前host还有Python裁剪、递归状态、BN/RNG隔离，整网编译不是此次有证据支持的必要修改。

[SeqTrack3D](https://arxiv.org/html/2402.16249v1)通过历史点云与历史框共同处理稀疏场景；
其[作者PointNet代码](https://raw.githubusercontent.com/aron-lin/seqtrack3d/main/models/backbone/pointnet.py)
采用Conv/Linear、BatchNorm和池化。论文里的局部编码器LayerNorm不意味着应把本项目PointNet的BN全部换掉。
据此，本项目保持共享观测结构，将无效槽排除作为可靠观测基础。历史点云和历史框的有效信息继续参与预测，
不能因为当前缺点就把整个历史查询也清零。

## 对三模块和论文目标的影响

B1依赖真实时间、历史框和实际crop获取新增点，B2在新增点中保留三个目标假设，B3对六个实际动作估计收益。
BN是否重算没有增加上述任何信息。为了进一步涨分，现阶段仍应先完成同状态链路诊断和闭环S/P：
目标是否在可达范围、是否进入support/256点、正确模式是否存在、B3是否利用了正确模式。
显存余量本身不构成扩大宽度、记忆或候选数的实验依据；这些改变需要对应瓶颈证据。

八步roll-in保留。它改变训练访问的递归状态分布，和只是重建同一个BN计算图的“重算”是不同操作；
前者有方法上的训练目的，后者是工程资源取舍。两者不应一起开关。

## 当前代码与配置

`cfgs/ct_seqtrack/30_formal_base.yaml`：

```yaml
ct_b0_masked_bn_recompute: false
```

- false：部分有效BN直接计算，同样只更新一次running statistics。
- true：使用上一轮验证的局部反向重算，作为显式低显存选项。

host将此值统一传给Seg/Mini/FeaturePointNet中的BN；全有效普通BN与少于2有效元素的处理不变。
开关不新增可训练参数、不消耗初始化RNG，纳入执行/恢复身份，三臂使用相同设置。
启动仍使用`PYTORCH_CUDA_ALLOC_CONF=backend:native`；新命令见[mini启动文档](CTSEQTRACK_V30_MINI_LAUNCH.md)。
同步时需包含`models/seqtrack3d.py`、`utils/masked_observation.py`、`utils/v30_contracts.py`和共同base YAML；
此前排序修复及命令生成器同样应保留。没有同步或运行服务器任务。

本轮定向回归**102 passed / 2 skipped，35.23秒**。默认直算和可选重算分别对照首次v30，
真实完整B0前向、loss、梯度、BN、Adam和RNG逐位一致；三臂默认共享更新一致，16份配置检查通过。
两项跳过是CUDA BN；实际CUDA占用和速度待修复版实跑，不据CPU等价或存储量声称涨分。

## 同形状CPU短对照

为验证取舍本身，另用当前实际PointNet源码做单线程CPU小样本：Seg `[2,14,4096]`、
Mini `[2,13,4096]`、Feature `[8,14,1024]`，来自同一B0 query的有效mask，第一行缺一个历史帧。
每模式预热一次，再按直接/重算/重算/直接各测两次；保存量按底层storage去重，包含输出平方均值损失。

| 模式 | 三PointNet前后向平均 | 保存量 |
|---|---:|---:|
| 直接 | 1.8484秒 | 702.139MiB |
| 重算 | 2.1427秒 | 401.561MiB |

本CPU小样本重算少42.81%保存量、多15.9%时间。它证明了实现中的取舍，并不代表CUDA慢15.9%，
也不包含完整host、数据准备和roll-in耗时；不拿它预估60轮训练时间。
本测量包含损失保存量，不能把401.561直接与上一轮不含此损失的400.731判作回归。
原始记录见[本轮验证](../artifacts/ct_checks/20260915_v30_memory_tradeoff/REPORT.md)。
