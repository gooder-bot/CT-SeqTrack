2026-10-26。服务器原版 v38 `14c3b2f` 的三组已完成；本地活动代码仍为 clean1，本次未部署 clean1、修改模型或启动新正式训练。用户本轮明确授权 profile，并指定 GPU0。完整原始证据、复算代码和性能 trace 位于 [本轮目录](../artifacts/ct_checks/20261026_final_profile_review/)。

## 2. 现在最值得修的问题

| final60 风险 | B1 standard | Full |
|---|---:|---:|
| 中心误差 >10m | 103 | 235 |
| 持续失跟累计帧 | 291 | 418 |
| trusted 写入 | 1235 | 744 |
| 不满足真实可信事件的写入比例 | 37.25% | 34.41% |

Full 新增 132 个 >10m 帧，其中 114 来自低运动端点。末三轮均值也有同方向尾部退化，不能只看平均分小幅上涨。

逐帧证据进一步区分三类问题：

- **观测核验失败：**235 个严重漂移帧中，213 帧仍选 q0。另一个独立统计集合中，有 173 个预测端点最终 exactIoU<0.1，但同态现有候选已有 exactIoU≥0.5，其中 167 帧仍选 q0。这说明当前背景/失配观测没有被可靠识别。
- **搜索范围失败：**严重漂移的 235 帧中，173 帧原始点云有目标、当前 crop 却没有目标。只在原 crop 内新增对应，无法直接解决这部分失跟；需允许“不匹配”，并触发受控原云重搜索。目标根本不在原云的帧不能凭空恢复。
- **位置修正不足：**170 个预测端点的所有候选 exactIoU<0.1，其中 74 帧 crop 里还有至少 3 个真实目标点。仅改善选择不够，还需要由真实对应支持的有限纠偏。

同态单步 oracle 为 59.7101/72.3206，比实际高 7.6871/9.1893 pp；这是已访问状态上的被动单步空间，不是闭环可兑现成绩。T 最高分箱平均预测 0.9707，实际可信事件频率 0.7286，不能称为已校准概率。

**早期高分不代表可以直接挑早期 checkpoint 发论文。** epoch3 几乎保持首框：q0 选择 0 次、可信写入 0 次、trusted propagation 2028 次，得到 60.4420/72.9737。epoch1–3 到 late3，运动端点提高约 12.32/17.06 pp，低运动端点下降约 7.49/8.28 pp。更准确的问题是“学到了运动，但低运动稳定性流失”，而不是所有能力都越训越差。该行为关系不是单变量因果归因。

## 3. GPU0 实测与解释边界

在原服务器 Python3.9 / torch2.0.1+cu118 / A40 上，严格加载本次 Full epoch060 的模型参数，执行一次性工程测量。训练使用真实 batch16、1024 点、成熟 W=1/4/4/8 窗口，4 次预热、12 次分段测量、1 次 profiler、3 次无 hooks 测量；推理为 batch1 连续递推，共 65 个预测端点、6 条轨迹，其中 48 次分段测量。

只上传本轮独立 artifacts 脚本；没有安装包、修改生产源码/原输出、保存工程 checkpoint 或启停他人任务。单 CPU 线程、workers0、nice19、idle I/O priority、显存额度22%、每步测量外让步0.2秒、600秒期限。按用户指定与 GPU0 已有进程共用；出现白名单之外的新计算进程则结束自身。两次 profile 都已退出并释放显存，原 GPU0 进程仍存在。

**共享 GPU、繁忙主机和逐阶段同步使墙钟只能用于本轮样本诊断，不能报告为独占 FPS，也不能证明对已有任务完全没有性能干扰。** 两次记录的源码前后 SHA 均与旧登记一致；这不是 clean1 配对测速。训练只载入模型参数，Adam 为新建的临时优化器，不是正式续训。

训练分段耗时的平均值如下；分母是互斥 `stage/*` 平均耗时之和约 3004 ms，模块嵌套时间未重复叠加：

| 阶段 | 平均 ms/batch | 样本分段占比 |
|---|---:|---:|
| acquisition 标签与相关诊断 | 862 | 28.7% |
| CPU 数据/状态整理 | 681 | 22.7% |
| 反向传播 | 422 | 14.0% |
| 完整网络前向 | 413 | 13.7% |
| loss | 156 | 5.2% |
| H2D 与缓存建立 | 121 | 4.0% |
| 原始数据读取 | 114 | 3.8% |
| 其余 prior、诊断、Adam、commit 等 | 236 | 7.9% |

训练峰值 allocated **7064.85 MiB（6.90 GiB）**，reserved **7382 MiB**。一次训练 profiler 中实际 kernel 时间约 **524.8 ms**，B0 前向约159.7 ms，三个 attention 模块前向约21.9 ms；后者不包含其反向，不能直接当 FlashAttention 整体收益上界。逐元素乘加/where 与归约约占 kernel 时间55%，提示应同时优化 masked BN、掩码与大张量搬运，不能只盯 attention 矩阵乘。

更直接的优化机会是 padding：训练分段样本平均仅 **8.49%** 输入槽为有效点，推理分段样本仅 **3.51%**。当前 mask 排除无效统计与梯度，但许多1×1卷积和逐元素操作仍计算完整补齐尺寸。应优先尝试有效点压紧、按原槽散射/分组池化、融合掩码归约；保持有效计数、running variance、空帧及少于2点等语义。它可能比进一步压缩已有空间 token 更适合当前瓶颈，但尚未实测优化收益。

上表 acquisition 阶段还含设备回传、统计和字段材料化，不能把全部862 ms归给9×9枚举；需要进一步细分。推理同名阶段不执行训练标签网格。

推理样本分段均值约733 ms、中位431 ms；无 hooks 的另8帧均值约1247 ms，表明采样与争用波动显著。一帧 profiler 实际 kernel 约9.36 ms，其中 attention 前向约2.15 ms，而该帧墙钟463 ms。CPU调度、同步、微小操作启动以及共享设备等待都需检查；不能把剩余时间全部归因于某一段 CPU 代码。

复现脚本、逐阶段 JSON、Chrome trace、分析见 [profile 审查](../artifacts/ct_checks/20261026_final_profile_review/profile/PROFILE_REVIEW.md) 与 [harness 使用说明](../artifacts/ct_checks/20261026_final_profile_review/harness/README.md)。

## 4. 下一步推荐：工程底座先行，算法两条线并行

**第一步：先消除真实热点，再接 FlashAttention/BF16。** 当前去掉 B2 后，9×9 acquisition 标签仍在训练，输出却不再控制实际搜索。先用clean1，处理有效点压紧/散射、标签向量化、预计算旋转/去重、合并小型 H2D/D2H 和重复几何，检查 masked BN/掩码归约；将特征层 BF16 与真正命中融合后端的 SDPA/FA2 放进共同高效底座。坐标/递推状态和敏感归约可继续 FP32。保持头维度、mask、全空行、dropout语义，不能只替换 API 就宣称 Flash 已启用。新环境独立配置，不覆盖现有复现实验环境。

**第二步：主涨分线 G = 短窗目标对应、明确 no-match、有界纠偏、按需重搜索。** 保留初始目标小模板和少量可信历史，用覆盖率、几何残差、背景竞争、未匹配率判断当前观测。正常帧做有限位置/yaw 修正；证据失配时围绕预测和可信位置进行受控原云搜索，再核验候选。新修正候选重算自己的支持和可信资格。保留原 q0，传播不自动获得观测资格；不恢复旧 B2 的整条 memory/vote/mode 链。搜索和 token 的额外成本要计入总延迟。

**第三步：并行做 M = MTP 启发的真实时间 2/4 步预测监督，优先考虑替换旧 acquisition 辅助。** 这比一直保留已无实际搜索用途的昂贵旧目标更值得研究。但旧 acquisition 会通过共享 context 影响 B1，因此删除它是研究变量，不能当死代码清理。未来标签缺失只屏蔽相应辅助损失，不删除原有主任务端点。先保持逐帧完整观测，验证缺测/启停/长时间漂移收益。

推荐固定一个实现后做以下五组，而不是 MTP、Flash、几何每项都串行消耗60轮：

| 组 | 目的 |
|---|---|
| E：共同工程底座的原辅助强 B1 | 保留真正强基线 |
| E0：去 acquisition 的 B1 | 单独识别删辅助的影响 |
| E0 + M | 多步预测监督的贡献 |
| E0 + G | 对应/纠偏/重搜索整套观测机制 |
| E0 + M + G | 预先指定的完整新方法 |

在同 batch16/原采样预算下，五组为300 epoch/358,500更新；这是建议，**本次未登记、未启动**。若只做四组，把“去 acquisition＋加 MTP”明确作为完整的辅助任务替换因素，不能单独归功于 MTP。若论文要单独声称几何核验优于原 B3，再补同底座原 B3 对照及“只核验、不纠偏”的定向消融。每组同新底座、scratch、同预算，固定 final60/late3；旧 FP32 结果不冒充新 BF16 的严格同底座对照。

**最后开发真正的自适应计算。** 轻量预测＋独立低成本当前观测核验，易帧减少重模型执行，失配/重找时完整模型回退。现在的 B3 必须先跑完整 B0，因此直接接 MTP 不能省掉 B0。这个方向可以与前面并行做原型，但独立测“精度—延迟—严重漂移”，不称为具有语言模型原算法分布等价保证的投机解码。

论文主线可围绕“可核验的预测—纠偏与计算分配”。FlashAttention 是工程部件，多步监督是借鉴思想，目标对应、失败恢复和计算决策的联合机制才是需要用结果证明的贡献。方向固定后，优先投入第二 seed 和更广数据/场景，避免继续在 mini_val 上大量试配方；本轮单 seed、mini Car 不支持 SOTA 或跨数据集泛化宣称。
