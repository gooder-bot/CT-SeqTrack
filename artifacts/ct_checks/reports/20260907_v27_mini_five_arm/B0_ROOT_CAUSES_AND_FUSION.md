# B0 为什么先失跟：根因复核与时空融合方案

2026-09-07审计，2026-09-08补充历史正常B0对照；审计代码 `8b8b8d9`。本次只读正式模型、配置、历史提交和实验输出，新增分析与真实模块的合成复现。没有修改训练代码、重训或运行真实 nuScenes 反事实评测。不参考 TrajTrack。

## 1. 结论和证据边界

针对`astra重构`的父提交实际函数对照与新增受控探针，见[astra提交专项结论](ASTRA_COMMIT_B0_VERDICT.md)。该补充将新增prior/稀疏/空观测变化与旧主干问题分开。

**应将修复 B0 提到 B1/B2/B3 调参之前。** 当前低分有真实的早期观测失败和递归放大，不能只用“mini 数据少”或“评测集合不同”解释。本轮确认了此前形状/运行检查未发现的训练目标与输入语义错误。

最需要优先处理的是：

1. **CT 的 B0 box-aware 损失实际重复计算，五臂、四个观测 view 全部受影响。** 配置权重1，实际该项梯度系数2；reference只计算一次。
2. **v27 将预测历史错误地赋予训练中 GT 历史对应的0/1 prior。** 原推理在首个查询之后采用0.2/0.8；合并输入构造后把candidate0误当成历史可靠性的依据。
3. **帧/通道拆分错误，且历史有效mask未进入Transformer。** 二者来自原 SeqTrack 实现，但CT又将错位特征绑定真实点ID，破坏B2的新增接口。
4. **B0训练仍是GT附近的小扰动；预测递归mechanism不更新B0。** 当前点为空时推理又强制reference，历史分支即使产生位移也会被覆盖。

前两项是明确的CT相对reference的训练/输入偏差；第三项是继承错误与新增特征接口错误；第四项是训练与部署合同的局限。它们的存在已有证据，**每项分别造成多少S/P损失尚未经过控制实验，不能宣称已经用一个bug解释全部降分**。

原历史SeqTrack使用8个mini_train场景并在官方mini_val评价；本次CT训练6场景，现有验证是scene-0061内部dev。两者不能直接相减得到“退化幅度”，但这不影响下面对当前轨迹失效的判断。官方mini_val、匹配reference及late-3仍需补齐。

### BC双计和继承错误，为什么仍要修但不能包办历史解释

历史`049de82`的高分B0**同样走BC双计**：当时compute_loss第5274行别名、第6853/6854行双加，safe_auto正式取事务loss。错误reshape和忽略history mask也已存在。因此：

- BC双计是确定的声明目标不一致，必须修；但不是8月24日到25日才引入的退化开关。
- 错误reshape和mask是确定的语义问题，应修；但历史高分证明网络可以在有这些缺陷时偶然达到较高结果，不能承诺修它们必回到53分。
- v27的预测历史硬prior、空current强制reference、稀疏点保留/损失mask与6/1/1集合，是比历史v25新增的输入和分布改变，应分别验证。

这里区分的是“实现不正确”与“已经证明它造成某次分差”；二者不能混为一个结论。

## 2. 失效发生在什么位置

B0第60轮dev包含12条轨迹、321帧，其中309个预测帧。全帧S/P为17.952/15.553。

| 现象 | 数量 | 含义 |
|---|---:|---|
| 预测误差>2m | 260/309 | 大部分递归输出已经失跟 |
| 预测误差>10m | 137/309 | 已远超正常局部修正范围 |
| base没有任何点 | 117/309 | 进入reference停留策略 |
| base没有目标点，含空base | 231/309 | 后半程观测证据严重退化 |
| 曾出现>2m误差的轨迹 | 11/12 | 不是单条离群轨迹造成 |
| 首次越界后从未恢复≤2m | 10条 | 错误状态具有很强的持续性 |
| 首次越界时base已包含全部全局可见目标 | 8/11 | 初始失败不能归因于先裁丢目标 |

其余3次首次失跟当帧全局就没有目标点。全局目标点计数仅用于事后诊断，不能用于实际采样或动作决策。

轨迹7是清楚的反例：

| 查询帧 | base目标/全局目标 | B0误差 |
|---|---:|---:|
| 1 | 8/8 | 2.64m |
| 2 | 25/25 | 9.24m |
| 3 | 0/仍有可见目标 | 此时才裁丢目标 |

因此更符合数据的顺序是：**稀疏观测/目标身份或位置回归失败 → 错误预测成为下一帧锚点 → 裁剪逐渐丢失目标 → 不可靠历史继续被信任 → 恢复失败**。后续B1/B2的证据不足，一部分是这个链条的结果。

轨迹8则从全局无目标、base全空开始，前三个查询误差约3.98→7.96→11.94m。reference停在旧位置，目标继续移动。只有首帧框而没有可推断速度的历史时，融合也不能保证恢复未知运动；后续已有可靠运动历史时，应允许显式的无观测预测。

## 3. 已确认的代码与接口错误

### 3.1 B0事务损失的Tensor别名导致BC双计

`models/seqtrack3d.py:5809`：

```python
b0_transaction_loss = loss_total
```

这里没有形成独立数值快照。第7498行执行：

```python
loss_total += weighted_bc
b0_transaction_loss = b0_transaction_loss + weighted_bc
```

第一行原地更新共享Tensor，第二行再给事务加一次BC。正式CT反传取的是`loss_b0_transaction`，原reference取的是只加一次BC的`loss_total`。

需要以实际训练路径判断，而不是只读旧辅助view函数：五臂observation期间全部关闭插件；普通observation payload也没有`ct_b0_auxiliary_only`标记。四个candidate的loss切片都走这条双计路径。旧online auxiliary microbatch有非原地加法、只加一次，但它不是这五次正式observation运行采用的路径。

令A是其余B0损失、C是按配置加权的BC损失，实际目标为：

\[
L_{\rm actual}=0.5(A_0+2C_0)+\sum_{i=1}^{3}(A_i+2C_i)/6.
\]

计划要求每个view只包含一份C。真实模型5臂×4view复现确认，事务与普通总损失差额就是一份BC；BC权重变化对应的额外梯度为预期单份梯度的2倍。

`git blame`将赋值及两行BC加法定位到`25586b27`（2026-08-13）的损失分离改动；它早于v27并被继承。不能将它说成2026-09-05重构首次引入。

补充历史反证：049de82的50.690/59.280高分B0也优化双BC，见1A。因此这项错误必须修，但不是历史高低分跳变的充分解释。

这会改变box-aware回归与目标分割、中心/运动任务的梯度平衡。BC输出又参与coarse motion输入，所以影响不限于日志的一项loss。**它不是“总loss全部放大两倍”，也不保证修掉就恢复所有分数。** 五臂同受影响，不能用它解释五臂之间第一次optimizer更新的数值差异。

建议：各模块通过显式命名loss项构造自己的标量；避免先别名再用`+=`。验收应检查数值和梯度系数，不只检查loss有限。详见[b0_bc_loss_execution_path.md](b0_bc_loss_execution_path.md)。

### 3.2 candidate身份被误用为历史框的可信度

`utils/v27_input.py`中的推理输入固定`candidate_id=0`；这是canonical view身份，本身合理。但`datasets/sampler.py:1613`仅在candidate非0时把历史prior的0/1转换为0.2/0.8。

训练的candidate0使用GT历史，预测递归的candidate0使用预测历史，两者来源不同；统一输入函数没有统一它们的置信语义。真实第8帧推理夹具的3帧历史prior仍只有0/1。原推理在首个查询之后软化该prior。

建议：保留candidate0身份，新增/使用明确的历史框来源与质量字段。初始化框、扰动历史、预测历史分别构造prior，训练/推理共用规则。不要用当前GT判断历史可靠性。这是来源语义回归，不是已经发现当前GT泄漏。

### 3.3 拆帧实际上混合了通道与时间

`models/seqtrack3d.py:3752`把`x:[B,C,L*N]`直接reshape成`[B*L,C,N]`，缺少帧轴和通道轴交换。正确语义为：

```python
solo_x = x.reshape(B, C, L, N).permute(0, 2, 1, 3)
solo_x = solo_x.reshape(B * L, C, N)
```

当前C=14、L=4时，所谓“当前帧”块的通道全部来自部分box-distance通道。仅扰动当前XYZ，其最后一个伪帧输入不变；正确逐帧输入会变化。当前XYZ实际混入其他伪帧。SegPointNet/coarse及全局attention仍有其他XYZ路径，因此不能说整个B0完全不读取当前点云。

更严重的CT新增后果：第二层64维输出又被当成真实`[B,L,N,64]`，交给B2绑定真实坐标、point ID、foreground/context role。**点ID正确传播，也不能修复“特征属于另一个伪帧/通道”的问题。** 当前点与历史记忆的身份相似度没有预期的逐点对应基础。

该reshape存在于冻结原SeqTrack中，因此只能说是继承语义错误，不能把相对原版分差全部归因于它。修复改变学习语义，即使参数shape不变、checkpoint能加载，也必须scratch验证新模型。

### 3.4 valid mask停留在接口，没有形成完整前向合同

`models/attn/Models.py:125`接收history `valid_mask`，但local/global encoder和decoder调用没有消费它。真实Transformer合成复现：同输入改变mask，输出差0；mask保持无效，仅改变无效历史特征，当前框输出改变。这确认了无效历史影响输出的路径，合成数值不代表真实checkpoint的误差量。

此外，点级padding/unique mask目前主要用于损失、点身份和质量统计，不能屏蔽SegPointNet/FeaturePointNet的BN与pooling。N=0的padding也带有time/prior等非零通道；N=1/2重复真实点是采样槽，不是1024个独立观测。

应区分三个mask：历史时间步是否存在、该时间步的点观测是否有效、物理点是否唯一。已有框历史但点云为空的时间步仍可提供运动信息。无效key进入attention/pooling前必须处理，全key无效也应有明确定义；参考框序列监督需排除不存在的历史槽。若改归一化/池化方式，要登记新的观测版本，不静默修改原reference。

真实复现：[输入语义探针](reproduce_b0_input_semantics.py)、[特征与mask探针](reproduce_b0_feature_contract.py)。这些探针证明缺陷存在，不是修复验收通过。

## 4. 数据耦合为何让一次失误持续放大

### 4.1 B0没有从真实递归误差中学习恢复

当前observation主要是GT历史及约±0.3m平移、±1.5°yaw扰动，canonical零扰动权重为0.5。推理实际遇到几米乃至十几米误差；加大epoch不会自动消除这种条件分布差异。

实际B0日志也支持“训练拟合正常、递归部署失败”这一判断：候选加权总loss从epoch1的7.362降到epoch60的0.351；训练日志的前景准确率从约94.0%升到97.9%。后者是训练采样槽统计，不是dev唯一目标点识别率。各组件日志是在四candidate混合batch归约，缺少每view组件，不能把混合BC占比冒充精确加权loss占比。详见[b0_loss_components.json](b0_loss_components.json)。

mechanism虽然递归使用预测框，但B0执行临时eval+no_grad，损失只更新插件。因此“所有模块从epoch0训练”是真的，“B0在mechanism里学会了递归恢复”不成立。

建议在完成公共错误修复后，单独验证部署分布训练：保留正常观测，混入只由自身过去预测生成的历史状态/相关扰动；这些样本由B0自身观测loss更新。历史状态detach，当前点与GT标签按原因果边界分开。为保持臂间可比，公共训练流应由B0-only状态生成，不能让Full选择结果改变其他臂的B0输入。所有参数仍从epoch0训练，不冻结、不跨实验加载checkpoint。

这会改变旧v27 observation训练合同，应登记新实验版本，不能声称“其余训练条件未变”。首先不需要同时扩大所有扰动范围；先统计真实首错前历史误差，覆盖1–3m等关键过渡区，避免把绝大多数训练crop变成不可观测背景。

### 4.2 空current时训练要求运动、推理丢弃运动

`models/seqtrack3d.py:3831`在eval把无current点的最终局部框置零，即输出reference。训练模式没有该覆盖，仍计算框/运动回归目标。这是原v27计划明确选择的策略，但在117个空base预测帧上暴露了局限。

不能只新增历史fusion然后保留这段覆盖，并期待空帧恢复。建议定义并记录三种情况：当前有观测的正常定位、当前base为空但extension合法的证据恢复、全部当前证据为空而仅由历史支持的运动延续。最后一种应作为明确的无观测预测/动作训练和评测，不能把历史memory当成当前新增点。

评测保留全部帧。训练也不要通过删难例或GT reseed制造高分；对缺乏可辨识信息的输入，区分观测证据监督与历史运动/不确定性监督。

### 4.3 现有硬判决与特征压缩是后续可测的限制

seg argmax只对coarse motion点输入做硬筛，motion-state argmax也会使coarse位移二值化；FeaturePointNet仍读取完整x。它们可能使稀疏输入的微小分数变化变成较大coarse query差异，但没有逐帧logit/中间框，不能指认每次失跟都由硬门触发。

FeaturePointNet按采样序号把1024个64维点特征AdaptiveMaxPool成128槽，不是几何邻域采样。同一输出槽不同通道的max可能来自不同物理点，不能赋予它单一point ID或直接把它当带XYZ的点。

先补coarse/final误差、前景logit和unique点数的同帧日志；再分别测试soft targetness加权、几何池化等改变。不要在尚有上述合同错误时同时更换所有head。

### 4.4 下游模块还有独立问题，不能全归B0

B0确实决定后续历史、裁剪锚点和memory质量。但原报告确认的presence硬门残留、Full未装校准、约0.75m有界半径严重截断raw proposal，都是额外问题。修复B0不会自动修复它们。

同样，五臂共享B0初始化和前100个输入指纹，但首个Adam更新就出现数值分叉、最终B0权重不同。插件首次更新尚未发生，所以不能直接归因插件梯度污染；共同BC双计也不能解释跨臂差异。需在服务器记录梯度/Adam更新并与同臂重复对比，CUDA非确定性仍是待验证假说，不是本轮已确认的主因。

## 5. 时空融合：能加，首先放在B0逐点特征压缩之前

SeqTrack本身已有local/global Transformer与历史box query；“再加入时空Transformer”不是充分的新贡献。论文也强调点云序列与框序列共同建模。[SeqTrack3D原文](https://arxiv.org/html/2402.16249v1)

针对8/11次“首次失跟时base已经有全部可见目标”的情况，最合适的首选位置是：

```text
正确拆分的当前/历史点云与mask
    → FeaturePointNet前两层：64维、与XYZ/ID一致的逐点特征
    → 新增：当前base点 ↔ 可靠历史目标/上下文的几何与时间融合
    → PointNet后段与128-token压缩
    → 已有local/global Transformer和box decoder
    → B0 observation
    → B2读取detach的观测特征与extension，再由B3决策
```

B1依旧只根据过去状态在当前获取前生成prior；ST不改变这个因果顺序。

具体先实现一个可开关的小模块：

- 当前1024个点槽为query，过去3帧每帧选8个框内+4个上下文的唯一有效点，形成最多36个history token。
- 在真实点级表征上使用相对局部几何、预测框位姿对齐、effective time age、role和历史质量；背景token保留自身上下文坐标语义，不能全部按目标刚体运动强行warp。
- 一次cross-attention产生64维残差，连续质量门控加入当前特征。有效历史全空时残差为0；初始门使用小的非零值，让所有启用层从epoch0获得学习信号。
- 不把目标框内点全部当成目标，只将role作为先验。历史身份应同时比较目标prototype与上下文prototype，以减少错误框持续污染记忆。
- 必须把融合结果送入PointNet后段和B0 decoder。仅修改返回给B2的`second_layer_out`并不会提高B0。
- B0+ST的同一forward历史特征可以参与梯度；历史状态、采样索引detach；B2/B3消费B0特征时继续detach。现有`build_box_memory_tokens`会detach，不能直接复用后误称ST历史分支可学习。

目标/上下文条件可参考CXTrack，历史目标记忆和框先验可参考MBPTrack；这里的具体接入、时间与质量条件是针对本项目的设计建议，尚无涨分证据。[CXTrack原文](https://arxiv.org/html/2211.08542v1)、[MBPTrack原文](https://arxiv.org/html/2303.05071v1)

为什么不首先放B1或B2：B1的主要输入是框序列，职责是运动和获取；B2已有extension到base+memory的attention，增强那里能改进新增点身份，却不能改善B0-only，也覆盖不了没有novel extension的早期base定位错误。

如果希望保持观测网络原样，可另设计读取base+extension的候选refiner，但这将改变extension-only合同，需要新命名和消融。针对用户当前强调的B0先低分，优先B0-ST更直接。

详细模块/梯度设计：[spatiotemporal_fusion_design.md](spatiotemporal_fusion_design.md)。

## 6. 建议的执行顺序和完成判据

| 顺序 | 修改/实验 | 需要回答的问题 |
|---|---|---|
| 1 | BC loss显式构造、历史prior按来源、正确拆帧、有效mask、特征与点ID一致 | 训练目标和数据语义是否真正满足合同 |
| 2 | scratch公共修复B0；匹配协议的SeqTrack reference；补官方mini_val | B0失跟是否减轻，修复效果是否独立于数据划分 |
| 3 | 公共修复B0 + 一个点级ST模块；必要时另测部署分布训练 | 改善来自历史身份融合还是训练样本变化 |
| 4 | 同一观测干路接B1-CfC/GRU、B1+B2、Full，修presence和动作合同 | 新证据与选择动作是否带来额外收益 |
| 5 | mini验证通过后，350 train_track训练、150官方val正式评测 | 完整数据主结果是否支持论文贡献 |

模型和损失变化后的正式实验全部scratch，所有启用参数持续训练。旧checkpoint可用于prior/动作开关的同状态及闭环敏感性诊断，但不能替代纠正布局/新增ST后的从头训练。Full阈值依协议锁定；官方val不用于调阈值、选后端或选epoch。

必要的新验收应围绕语义：逐view BC数值和梯度系数正确；无效历史内容扰动不改变有效输出；正确拆帧后当前点影响对应current feature；N=0/1/2、重复ID和全部key无效均有确定前向；同一历史来源训练/推理prior一致；每臂同B0输入/BN/梯度/Adam检查；空当前时实际动作与监督一致。

效果诊断除S/P还应记录首次>2m时刻、1–2/3–8/9–32/更多目标点分桶、coarse到final误差变化、连续空crop长度、目标重现后重获帧数和全帧动作净收益。不能只看平均loss下降。

本轮可以确定的是修复优先级和融合位置。**当前代码尚未按这些新发现修复，不建议立即复跑五臂或开始30个完整数据训练。** 先恢复一个语义正确、可解释的观测干路，再检验模块收益。
