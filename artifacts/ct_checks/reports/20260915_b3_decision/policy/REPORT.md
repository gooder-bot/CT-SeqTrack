# B3 策略、递归与公平取舍审计

日期：2026-09-15。只读当前 HEAD `525eb54`、关键历史提交及已经同步的实验记录；没有修改生产代码、配置或训练任务，没有访问 TrajTrack。这里区分代码事实、合成反例和真实训练诊断，不能据此宣称某版最终分数更高。

## 1. 取舍建议

**以 v29 的有界动作即时效用 B3 为主线，比整体退回旧版“presence 硬门 + help/harm 概率乘积 + 经验风险晋升”更适合当前争取跟踪 S/P 的目标。** 保留结构合法性、显式执行动作、同状态反事实监督、训练接受动作后的状态覆盖和真实闭环策略拟合。这些修改增强了目标和部署行为之间的对应关系。

但当前 B3 只支持“局部有界纠偏的效用选择”，不具备概率校准保证，也没有学到明确的多步恢复价值。**去掉旧 H3 混合监督是合理的语义修正；把所有未来收益永远排除，则不一定契合长期稀疏跟踪的创新方向。** 如真实数据证明 H1 零收益压制了有益恢复，应引入定义明确、与策略连接的独立未来收益目标，不能简单恢复旧版同一 q 头的 H1/H3 混合。

第一优先级是修正阈值预筛的闭环等价假设，并使用已有 checkpoint 比较评分与动作。先证明当前 B2 生成的动作有可利用的收益，再决定 B3 是否需要更复杂的新网络或时间目标。

## 3. 当前动作与训练/部署状态的精确定义

### 3.1 真正执行的动作

`models/ct_v2/action_v27.py:11`：raw 相对 observation 的 XY 位移按 `r=min(0.5+0.5*dt, 2)` 裁剪，Z/yaw 保持 observation。dt≈0.5s 时半径≈0.75m。B3消费的动作特征包括实际有界 dx/dy、raw/radius 和裁剪比例，因此监督和输入都描述这个有界动作。

`utils/v29_policy.py:33`：

- never：不接受。
- always：接受全部有限且结构合法的候选。
- threshold：合法且 `q > threshold` 才接受，比较符号是严格大于。
- 没有 presence 硬门、当前 GT 或随机选择；结果 detach，由 host 唯一提交。

正常有限输入下，`main.py --proposal_mode bounded_always` 是现成同权重动作对照。严格接口核验应注意，该 host 分支只检查结构 availability 与动作几何有限性，而 router 的 always 还包含 B3 输入特征与 q 有限性。生产正常有限数据应一致；若存在非有限特征，两种控制不能混称为完全同一候选集合。`TrackerClosedLoopRunner` 的 `install_policy({'kind':'always'})` 使用 router 相同合法性，适合内部精确对照。

### 3.2 训练递归确已修正

`utils/v29_policy.py:16` 按 seed/epoch/真实 tracklet key 的稳定摘要固定整轨迹行为，比例为25% never、25% always、50% threshold0。`models/seqtrack3d.py:8401` 仅在机制事务应用，`:8425` 将 `ct_v29_behavior_final_boxes` 变换回世界坐标后提交。

这解决了旧机制流“训练只提交 B0、部署却提交 accepted”的明确差异。B0共享训练流仍独立，Full探索行为不能回灌B0。它是行为混合下的状态覆盖，**并不等于训练时处处执行最终拟合策略**；未来选出的非零阈值仍可能访问新的状态。

### 3.3 默认 Full 验证有一个重要解释限制

v29 Full 配置为 `ct_require_action_calibration: true`、`proposal_inference_mode: selective`，继承的策略路径为空。`utils/action_calibration_v27.py:375` 安装阶段先置 never 与 `calibrated=False`；`models/seqtrack3d.py:3242` 明确规定缺失、不匹配产物时回退 observation。

**因此，默认未拟合策略的第5轮 Full 验证应理解为同权重 observation 路径，不能拿来评判 B3 是否涨分。** 必须检查结果中的策略加载状态和实际动作数。训练中 mixed behavior 的约12% accepted 也不能替代部署接受率。正式 Full 应为对应 checkpoint 单独拟合内部策略后再评测。

## 4. 当前 H1 比旧 H1/H3 更清楚，但确有局限

`utils/v27_training.py:34–99` 对全部结构合法 canonical 候选监督 bounded action 相对 observation 的即时 Success/Precision 差；当前输出 q 为两项条件期望均值，help/harm BCE 是其即时平均效用符号的辅助监督。没有按 accepted、presence 或正收益筛选。

旧 v27/v28 在存在合法 H3 子集时，对同一个 gain 头施加 `0.5*全合法H1均方误差 + 0.5*H3子集未来均方误差`。这不等于每个状态监督一个固定三帧平均收益，且 H3 可用性/调度改变实际目标权重。更早版本的有益标签还要求即时中心误差改善超过 margin 且 IoU 不降，有合法 H3 时再要求未来同时达标，无目标存在则作为有害。那是较保守的几何改善条件，和当前即时平均 S/P 符号不是一个任务。

当前 H3 的两个分支只在当前帧分别注入 observation/bounded，然后未来两帧都回退 B0；`utils/v27_training.py:221–246`。它测量的是**单次干预后 B0 续推**，不是反复执行某个 B3 策略的长程价值。因此即使恢复 H3 loss，也不能直接宣称优化了真实 Full 长期回报。

H1 的已验证盲区是：若动作前后都无重叠、中心误差均>2m，较大的几何改善仍得到0 S/P差；3m→2.25m 的合法局部动作就是反例，而2.01m→1.99m仅2cm改善可能跨过Precision档位。对应 `20260914_code_audit/b3/diagnostic_results.json`，是指标反例，不是当前数据发生率。

未来改进应先统计 `H1=0且几何明显变好`、`H1≤0但真实固定策略H步回报>0` 的比例和可识别性。若它们占主要恢复机会，可测试分离的 `Q_H(s,a)`/advantage 或明确折扣收益，再在决策中显式使用。仅加几何辅助 loss、部署仍只看H1 q，并不能保证愿意接受第一步零即时收益的恢复动作。

## 5. 概率乘积与期望效用，哪个更适合涨分

旧 `p_help*(1-p_harm)` 只反映符号概率，忽略收益/伤害幅度，也不是数学上已校准的“安全概率”。当前 q 在状态与候选固定、预测正确时直接对应“接受相对拒绝的期望即时指标差”，在即时二选一目标下更自然。

一个仅说明原则的例子：动作A有90%机会+0.001、10%机会−0.1，期望−0.0091，旧分0.81；动作B有55%机会+0.05、45%机会−0.01，期望+0.023，旧分0.3025。旧单阈值无法只接受B而拒绝A，期望效用能区分。当前数据是否呈现这种分布尚未测量。

旧“有害率上界≤5%”在用户优先低风险的目标下可作为人为运行约束；但用户当前主要目标是涨S/P，单独控制有害次数不计严重程度，可能否决净收益为正的策略。当前经验闭环拟合不是统计安全保证，应保留S、P、伤害严重度与恢复尾部诊断，而不恢复旧硬门作为默认主线。

## 6. 阈值预筛仍有实质缺陷，可以不重训检查

当前 `utils/action_calibration_v27.py:229–262` 在 never 轨迹上取41个分位阈值，以动作 mask 的 bytes 去重，然后按同状态一次替换的效用排名筛选最多3个阈值。后面的 `calibrate_actions_v27` 确实重跑真实闭环，v29还确保 always、never 都参与。

问题是**在 never 状态下 mask 相同，不代表第一次接受动作后继续产生的 q 相同**。已有真实筛选函数合成反例中，τ=.2与.5在never轨迹mask一致，.5被删除；动作改变状态后下一帧q=.4，两策略行为不同。该构造闭环U为never62.5、τ=.2为45、被删τ=.5为75。它证明筛选不完备，不证明真实 nuScenes 改进12.5分。

建议只按阈值数值去重；若预算仍为最多3个阈值，固定包含0并覆盖不同分位区间，或在相同总闭环预算内先粗后细。任何少量候选搜索仍是近似搜索，不能声称全局最优。改变筛选协议不改变权重，但需要独立的策略产物/协议身份，不能冒用现有 `internal_closed_loop_five_v1` 结果。

## 8. 不重训与需要重训的公平比较

### 已有 checkpoint 可以做的第一阶段

同一 Full checkpoint、同一个后端、同样数据/点采样/动作半径/上游权重，在所有策略下从首帧独立完整闭环：

1. never/observation。
2. bounded-always，尽量使用同一 router合法性。
3. 当前q配原拟合策略。
4. 当前q配数值去重/覆盖不同区间的拟合；与3匹配拟合场景和闭环预算。
5. 用现有help/harm头计算旧公式的评分对照，采用匹配预算的内部拟合；**这叫旧评分公式对照，不是旧B3复现**。

CLI已有 `--proposal_mode observation`、`bounded_always`、`selective` 与 `--ct_action_calibration_path`。`tools/ct_action_v27_runtime.py:60` 提供可调用 `TrackerClosedLoopRunner` 的 never/always/threshold；当前 main.py 和该工具**没有旧评分公式 score override 参数**。第5项需小型只读评测适配，独立记录评分定义并让动作真正进入后续状态，不能仅重排导出的旧轨迹，也不能编造现成命令。

同状态GT逐帧选择较好的observation/bounded可以估计候选正收益空间；它使用GT，只是诊断。即使把贪心oracle真实闭环运行，也不是全部未来动作序列的最优上界。

### 完整旧新B3消融需要下一版独立从头训练

共享同一适应化B0/B1/B2、样本顺序、执行动作和训练预算，只替换：当前H1目标、旧概率评分对应旧标签、清晰分离的未来价值候选。保持各臂从epoch0训练，不能冻结上游再称为同协议正式比较。不能直接比较v26/v28旧checkpoint与v29当前checkpoint的S/P，原因是上游、状态、采样、数据划分和损失均可能不同。

当前阶段优先做不重训的策略对照，避免在候选收益还不清楚时先开多个60轮长跑。

## 9. 采用与淘汰标准

- **先过正确性**：相同上游/动作/合法性；无GT进入输入或部署选择；全部端点与首帧一致；完整递归；策略匹配对应checkpoint；S与P口径完全一致。未通过则不讨论涨分。
- **局部可利用性**：按空点/少点、novel目标有无、共识目标占比、漂移距离、动作限幅和H1/H3符号统计。候选几乎无正收益时先改B2；候选有收益而q无法排名时再改B3。
- **真正闭环**：相对同权重never和always分别报告ΔS、ΔP、ΔU、动作率、有害率/严重度、首失跟、长空段后恢复及恢复延迟。单看loss、AP、风险或平均效用都不足以选最终B3。
- **选择区域隔离**：17个训练内部场景拟合，18个训练内部场景只做锁定诊断，披露参数训练重叠。用场景配对bootstrap表达经验不确定性，不能把帧当独立样本，也不能称为安全保证。若反复用18场景选方法，应承认它成为开发集，不能继续称最终未调参验证。
- **S/P分别决策**：当前拟合按U、S、P、较少动作排序，可能以更大的Precision收益换少量Success损失。用户希望两项均涨，应预先约定双指标非劣容差；不应仅因U提高就自动通过。候选Pareto支配当前方案优先；有取舍则列出明确ΔS/ΔP，由论文目标预先决定，不能事后改门槛。
- **弃用旧硬门的条件**：达到同样或更差S/P却明显减少有效恢复；或频繁退为never且无独立风险需求。它仍可保留为保守控制实验。
- **弃用新增复杂目标的条件**：同预算不能改善锁定闭环S/P/恢复、仅提高训练指标、增加计算却不增加有效动作，或收益只出现于额外搜阈值/挑epoch。先简化为当前H1 B3。
- **保留never的条件**：完整锁定评测确实更优。它表示当前上游动作+B3组合尚不能带来收益，不应通过最低动作覆盖强迫部署有害动作。
- **最终论文**：固定final60与58/59/60每个checkpoint分别拟合/评价再算术平均；不挑best epoch或seed。官方150场景不参与阈值、后端、epoch选择。当前前两轮数据只能用于问题定位与提出待验证取舍。

上述判断支持“保留v29清晰的即时效用与accepted递归，先修策略搜索和证据动作质量，必要时再加入明确未来价值”的路径；不支持立即整体回滚，也不支持现阶段宣称当前B3已最优或一定涨分。
